1. Orders API

Путь: SELLER APIs → Orders API
Текущая версия: v0
Доступность: Sellers only
Sandbox: Static

1.1 Обзор

Orders API позволяет программно получать информацию о заказах. С помощью этого API вы можете разрабатывать быстрые, гибкие и настраиваемые приложения для управления синхронизацией заказов, исследования заказов и создания инструментов поддержки принятия решений на основе спроса.

Примечание: Для маркетплейсов JP, AU и SG Orders API поддерживает заказы с 2016 года. Для всех остальных маркетплейсов Orders API поддерживает заказы за последние два года (более старые заказы не отображаются в ответе).

Ключевые возможности:

  • Получение списка заказов с фильтрацией
  • Получение детальной информации о заказе
  • Получение информации о товарах в заказе
  • Подтверждение статуса отправки
  • Работа с регулируемыми заказами (рецептурные товары)
  • Поддержка Amazon Business заказов

1.3 Примеры использования

  • Получение заказов с фильтрацией: Операция getOrders возвращает заказы, созданные или обновленные в указанный период времени. NextToken переопределяет другие критерии для получения заказов.
  • Получение информации о заказе: Операция getOrder возвращает информацию о заказе по указанному идентификатору.
  • Получение информации о товарах: Операция getOrderItems возвращает детальную информацию о товарах в заказе.
  • Подтверждение статуса отправки: Операция confirmShipment подтверждает статус отправки для указанного заказа.
  • Работа с регулируемыми заказами: Получение статуса и регулируемой информации для заказов с рецептурными товарами.
  • Amazon Business заказы: Идентификация бизнес-заказов по атрибуту isBusinessOrder.

1.4 Требуемые роли

  • Amazon Fulfillment
  • Buyer Communication

  • Direct to Consumer Shipping
  • Finance and Accounting
  • Inventory and Order Tracking
  • Pricing
  • Product Listing
  • Professional Services
  • Selling Partner Insights
  • Tax Invoicing
  • Tax Remittance

2. Catalog Items API

Путь: SELLER APIs → Catalog Items API
Текущая версия: v2022-04-01
Устаревшие версии: v0, v2020-12-01
Доступность: Sellers and Vendors
Sandbox: Static
Host: sellingpartnerapi-na.amazon.com
Schemes: HTTPS

2.1 Обзор

Catalog Items API предоставляет программный доступ к информации, содержащейся в каталоге Amazon. Используйте этот API для получения информации о товарах в каталоге Amazon.

Ключевые возможности:

  • Получение детальной информации о товаре
  • Поиск товаров по идентификаторам или ключевым словам
  • Получение сводной информации о товаре
  • Получение атрибутов товара
  • Получение классификаций по категориям
  • Получение размеров и веса
  • Получение идентификаторов продукта (UPC, EAN и т.д.)
  • Получение изображений товара
  • Получение рейтингов продаж
  • Получение связей между товарами (вариации, комплекты)
Примечание: Вендоры могут получать дополнительную информацию, специфичную для вендоров.

3. Listings Items API

Путь: SELLER APIs → Listings Items API
Текущая версия: v2021-08-01
Устаревшие версии: v2020-09-01
Доступность: Sellers and Vendors
Sandbox: Static

3.1 Обзор

Listings Items API предоставляет программный доступ к листингам продавцов на Amazon. Используйте этот API совместно с Product Type Definitions API для получения информации о типах продуктов Amazon.

Ключевые возможности:

  • Получение детальной информации о листинге
  • Создание и полное обновление листинга
  • Частичное обновление листинга
  • Удаление листинга
  • Поиск листингов по SKU, ASIN или идентификаторам
  • Предварительная проверка ошибок перед созданием/обновлением
  • Отправка медиа-атрибутов (изображения)
Совет: Используйте Listings Items API для индивидуальных обновлений (1x1). Для массовых обновлений используйте JSON_LISTINGS_FEED через Feeds API.

3.2 Операции API

3.3 Примеры использования

  • Получение деталей листинга: Возвращает детальную информацию о листинге Amazon для указанного продавца и маркетплейса.
  • Предварительная проверка ошибок: Проверка ошибок перед созданием или полным обновлением листинга.
  • Создание или полное обновление: Создание или полное обновление листинга Amazon.
  • Частичное обновление: Обновление отдельных атрибутов листинга.
  • Merge листинга: Обновление поля quantity в fulfillment_availability без указания других атрибутов.
  • Удаление листинга: Удаление листинга Amazon.
  • Отправка медиа-атрибутов: Отправка изображений и медиа-атрибутов.
  • Поиск листингов: Получение листингов по SKU, ASIN или идентификаторам.

Важные замечания

  • 1x1 обновления: Используйте Listings Items API для индивидуальных обновлений; для массовых используйте JSON_LISTINGS_FEED.
  • Полностью поддерживаемые типы продуктов: Проверьте Product Type Definitions для поддерживаемых типов.
  • Частично поддерживаемые типы: Используйте тип PRODUCT для частичных обновлений.
  • Результаты и проблемы: Отправки проверяют ошибки до обработки; актуальные данные отображаются в fulfillmentAvailability.
  • Атрибуты: Секция attributes отражает отправленные данные, а fulfillmentAvailability показывает актуальные данные.

4. Product Pricing API

Путь: SELLER APIs → Product Pricing API
Текущая версия: v2022-05-01
Устаревшие версии: v0
Доступность: Sellers only
Sandbox: Static

4.1 Обзор

Product Pricing API помогает программно получать информацию о ценах и предложениях для товаров на маркетплейсе Amazon. API разработан для помощи в создании автоматизированных решений, которые продавцы могут использовать для обновления и управления своими ценами.

Совет: Product Pricing API поддерживает разработку репрайсеров. Репрайсеры - это автоматизированные инструменты ценообразования, которые могут непрерывно отслеживать ценовые точки, цены конкурентов и другие релевантные факторы для корректировки цен продавца в реальном времени. Репрайсеры используют данные из Product Pricing и Notifications APIs для поддержания конкурентного ценового преимущества.

Ключевые возможности:

  • Получение информации о ценах товаров
  • Получение конкурентных цен
  • Получение предложений по листингу
  • Получение предложений по товару
  • Пакетные операции для множества товаров
  • Получение данных о Featured Offer Expected Price (FOEP)

5. Feeds API

Путь: SELLER APIs → Feeds API
Текущая версия: v2021-06-30
Доступность: Sellers and Vendors
Sandbox: Static

5.1 Обзор

Feeds API позволяет загружать данные в Amazon для управления бизнесом продавца. Существуют фиды для широкого спектра задач: создание листингов, управление запасами и ценами, подтверждение заказов и многое другое.

Важно: Поддержка Feeds API для XML и flat file product listings feeds устарела. Для получения информации о затронутых фидах и руководства по миграции обратитесь к объявлению об устаревании.
Примечание: Документы результатов фидов хранятся 28 дней.

5.2 Операции API

GET getFeeds

Возвращает информацию о фидах, соответствующих указанным критериям.

Вы можете отслеживать доступность инвентаря в реальном времени на уровне маркетплейса и получать детали, такие как:

  • Researching: Потерянные или поврежденные на складе единицы, которые активно подтверждаются в центре выполнения Amazon

Поддерживаемые типы уведомлений (EventBridge):

  • BRANDED_ITEM_CONTENT_CHANGE - изменение title, description, bullet points или images для ASIN
  • ITEM_PRODUCT_TYPE_CHANGE - изменение типа продукта для ASIN
  • LISTINGS_ITEM_STATUS_CHANGE - изменение статуса листинга
  • LISTINGS_ITEM_ISSUES_CHANGE - изменение issues для SKU
  • LISTINGS_ITEM_MFN_QUANTITY_CHANGE - изменение доступного количества
  • PRODUCT_TYPE_DEFINITIONS_CHANGE - новый Product Type или версия

Шаги настройки:

  1. Step 1: Create a destination - вызов createDestination
  2. Step 2: Configure Amazon EventBridge в AWS Console
  3. Step 3: Create a rule в EventBridge
  4. Step 4: Create a subscription - вызов createSubscription

Обзор

Надежность API зависит от правильного определения емкости и ресурсов для удовлетворения меняющихся потребностей вашего приложения. По этой причине Selling Partner API (SP-API) определяет планы использования для контроля количества запросов, которые вы можете делать к операции в течение определенного периода времени.

Алгоритм ограничения скорости

SP-API использует алгоритм token bucket для ограничения скорости запросов к API. Алгоритм основан на аналогии с ведром, содержащим токены, где каждый токен можно обменять на запрос к API.

Ключевые принципы:

  • Токены: SP-API добавляет токены в ваше ведро с установленной скоростью в секунду до достижения максимального лимита ведра (burst rate).
  • Запросы: Каждый запрос API вычитает токен из ведра. Throttling происходит, когда токены недоступны.

Факторы, определяющие планы использования

  • Операция API: Каждая операция имеет предопределенные лимиты rate и burst.
  • Пара продавец (аккаунт) и приложение: Большинство операций ограничены по скорости для пары аккаунт-приложение.
  • Регионы и маркетплейсы: Аккаунты, специфичные для маркетплейса, имеют отдельные лимиты.

Типы планов использования

  • Стандартные планы: Статические лимиты для всех вызывающих (например, 10 запросов/секунду, burst 20).
  • Динамические планы: Автоматически корректируются на основе бизнес-метрик.

Как найти ваш план использования

  • Документация API reference: Каждый раздел содержит лимиты скорости.
  • Заголовки ответа: x-amzn-RateLimit-Limit может указывать лимиты для ответов 20x, 400 или 404.

Обработка ответа 429

Реализуйте стратегии back-off. Используйте заголовок x-amzn-RateLimit-Limit, если он доступен.
